## Phase 2b — American Options and Visualizations

### American vs. European: one extra choice at every node

A European option can only be exercised at expiry. An American option can be exercised at **any point** up to and including expiry. That extra freedom is the only difference between the two — and it turns out to change almost nothing about the code, because it only affects one line inside backward induction.

At every node (except the final row, which is unchanged), the model now computes two numbers and keeps whichever is larger:

- **Continuation value** — what the node was already worth in the European model: `(1/R) * [q * value_up + (1-q) * value_down]`, i.e., "hold the option and let it ride."
- **Immediate exercise value** — the payoff if the holder cashes in right now, using that node's own stock price: `max(S-K, 0)` for a call, `max(K-S, 0)` for a put.

A rational holder would never choose the worse of the two, so the node's actual value is `max(continuation, immediate exercise)`. Nothing else in the tree — the forward pass, q, R — needs to change.

### Two results that confirm the logic is correct

**American call = European call.** For a stock that pays no dividends, it's a well-known result that early-exercising a call is never optimal — you'd be giving up the option's downside protection (the payoff can't go below 0) and the time value of money (paying K now instead of later) for no offsetting benefit. The code confirms this directly: running the American and European call pricers with identical inputs produces matching prices at every N, to four decimal places.

**American put > European put.** For puts, early exercise genuinely can be worth it — if the stock has already crashed, exercising now to collect K in cash (which then earns risk-free interest for the remaining time) can beat waiting. The code confirms this too: the American put price comes out consistently higher than the European put price across every N and every volatility level tested, never equal or lower. Both results match what the theory predicts, which is a stronger check than "the code runs without errors" — it's a check that the code respects real no-arbitrage relationships.

### Visualizations

Four plots, generated by varying one input at a time while holding the others fixed (S0=100, K=100, σ=0.30, r=0.05, T=1 year, N=100 unless otherwise noted):

- **`volatility_vs_price.png`** — call price vs. σ. Rises monotonically. Higher volatility widens the spread of possible stock prices at expiry in both directions, but the payoff `max(S-K,0)` is floored at 0 on the downside and uncapped on the upside — so wider spread only ever helps the option holder, never hurts.
- **`strike_vs_price.png`** — call price vs. K. Falls monotonically. A higher strike means a worse deal for the call holder (paying more to buy the stock), so the payoff — and the price — can only shrink as K rises.
- **`time_vs_price.png`** — call price vs. T. Rises monotonically, for the same underlying reason as volatility: more time gives the stock more opportunity to move, and that added uncertainty is a one-sided benefit to the option holder given the asymmetric payoff.
- **`american_vs_european_put.png`** — American vs. European put price, both plotted against volatility. The American line sits above the European line across the entire range, confirming that the early-exercise feature adds value and never subtracts it.

### Honest limitations

- Volatility, in all of these plots, is treated as a known constant. Real volatility is neither known in advance nor constant — this project doesn't address estimating it.
- The early-exercise comparison only checked calls and puts on a non-dividend-paying stock. Dividends change the call-vs-put early-exercise story meaningfully and aren't modeled here.
- These are single-variable sensitivity plots (one input varies, all others fixed) — real markets move multiple inputs simultaneously, and this doesn't capture interaction effects between them.
